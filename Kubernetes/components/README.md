## Задача

Проекту нужны:

- **База данных** — отказоустойчивая, 3 копии. Потребляет 4 ГБ ОЗУ и 1 ядро на копию.
- **Кеш** — отказоустойчивый, 3 копии. Потребляет 4 ГБ ОЗУ и 1 ядро на копию.
- **Фронтенд** — 5 копий. Потребляет 50 МБ ОЗУ и 0.2 ядра на копию.
- **Бекенд** — 10 копий. Потребляет 600 МБ ОЗУ и 1 ядро на копию.

Требуется рассчитать ресурсы, определить количество worker-нод, добавить запас на отказ минимум одной ноды и учесть служебные резервы.

---

## Шаг 1. Расчёт ресурсов приложения

Складываем все компоненты с учётом количества копий.

| Компонент | Копий | RAM на копию | CPU на копию | Итого RAM | Итого CPU |
|-----------|-------|--------------|--------------|-----------|-----------|
| База данных | 3 | 4 ГБ | 1 ядро | 12 ГБ | 3 ядра |
| Кеш | 3 | 4 ГБ | 1 ядро | 12 ГБ | 3 ядра |
| Фронтенд | 5 | 50 МБ | 0.2 ядра | 0.25 ГБ | 1 ядро |
| Бекенд | 10 | 600 МБ | 1 ядро | 6 ГБ | 10 ядер |
| **Итого** | **21 pod** | | | **30.25 ГБ** | **17 ядер** |

**Итого приложению нужно: ~30.3 ГБ RAM и 17 CPU.**

---

## Шаг 2. Служебные ресурсы на нодах

Помимо ресурсов приложения, каждая нода резервирует часть CPU и RAM для системных демонов (kubelet, containerd, sshd и т.д.):

- **kube-reserved** — для kubelet и container runtime.
- **system-reserved** — для OS-демонов.
- **eviction-hard** — буфер на вытеснение pod'ов при нехватке памяти.

Для ноды размером 8 vCPU / 32 ГБ RAM резервы составляют:

| Тип резерва | CPU | RAM |
|-------------|-----|-----|
| kube-reserved | ~0.2 ядра | ~1 ГБ |
| system-reserved | 0.1 ядра | 0.1 ГБ |
| eviction-hard | — | 0.1 ГБ |
| **Итого** | **~0.3 ядра** | **~1.2 ГБ** |

**Allocatable на ноду (8 vCPU / 32 ГБ RAM):** ~7.7 CPU и ~30.8 ГБ RAM.

---

## Шаг 3. Запас на отказ одной ноды

Требование: кластер должен выдержать выход из строя минимум одной ноды.

Если у нас **N нод**, после отказа останется **N-1**. Ресурсов оставшихся нод должно хватать для всех pod'ов приложения.

Также важно: 3 копии БД и 3 копии кеша должны распределяться по разным нодам. Значит, нужно минимум **3 worker-ноды**.

---

## Шаг 4. Варианты конфигурации кластера

### Вариант A: 4 ноды по 4 vCPU / 16 ГБ RAM

**Allocatable на ноду:** 3.75 CPU, 14.8 ГБ RAM

**После отказа одной ноды (3 ноды):** 11.25 CPU, 44.4 ГБ RAM

**Не хватает CPU:** 11.25 < 17. Не подходит.

---

### Вариант B: 5 нод по 4 vCPU / 16 ГБ RAM

**После отказа одной ноды (4 ноды):** 15 CPU, 59.2 ГБ RAM

**Не хватает CPU:** 15 < 17. Не подходит.

---

### Вариант C: 5 нод по 8 vCPU / 32 ГБ RAM

**После отказа одной ноды (4 ноды):** 30.8 CPU, 123.2 ГБ RAM

**Хватает с большим запасом.** Но есть более экономичный вариант.

---

### Вариант D: 4 ноды по 8 vCPU / 32 ГБ RAM

**Allocatable на ноду:** 7.7 CPU, 30.8 ГБ RAM

**После отказа одной ноды (3 ноды):** 23.1 CPU, 92.4 ГБ RAM

**Хватает.** 23.1 CPU > 17 CPU, 92.4 ГБ > 30.3 ГБ.

**Размещение pod'ов после отказа:** 21 pod на 3 нодах = 7 pod на ноду. Нормально.

---

### Вариант E: 3 ноды по 8 vCPU / 32 ГБ RAM (без запаса)

**После отказа одной ноды (2 ноды):** 15.4 CPU, 61.6 ГБ RAM

**Не хватает CPU:** 15.4 < 17. Не подходит.

| Параметр | Значение |

| **Количество master-нод** | 3 (для HA) |
| **vCPU на master** | 2 |

## Обоснование выбора

1. **Отказоустойчивость.** 4 worker-ноды позволяют пережить выход из строя одной ноды. После отказа остаётся 3 ноды с достаточным запасом CPU и RAM.

2. **Размещение копий.** 3 копии БД и 3 копии кеша распределяются по разным нодам. При 3 оставшихся нодах каждая копия гарантированно на отдельной ноде.

3. **Служебные резервы.** На нодах 8 vCPU / 32 ГБ RAM резервируется ~0.3 CPU и ~1.2 ГБ RAM на системные нужды. Остаётся ~7.7 CPU и ~30.8 ГБ для pod'ов.

4. **Запас на пики.** ~6 CPU и ~62 ГБ RAM после отказа покрывают кратковременные всплески нагрузки.

5. **Экономия.** Вариант C (5 нод) тоже рабочий, но избыточен. Вариант D (4 ноды) — оптимальный баланс между отказоустойчивостью, запасом и стоимостью.

### Рекомендация

- **Worker-ноды:** 4 × (8 vCPU / 32 ГБ RAM)
- **Master-ноды:** 3 × (2 vCPU / 4 ГБ RAM) — для отказоустойчивого control plane
- **Тип инстанса в Yandex Cloud:** `standard-v3`, platform `Intel Ice Lake`
